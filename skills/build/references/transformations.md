# Turning a reaction into a change

Use this when the request is a direction rather than a spec: bolder, quieter, more delightful, simpler, sturdier, more extraordinary. Infer what's actually wrong from the artifact and the user's reason, and keep the content, behaviour and successful relationships unless the request changes them. When two readings would produce meaningfully different results, show a small comparison or ask one decisive question.

Scope is sovereign for every one of these. "Everything else stays" is literal: touch only the named target, and add no colour, font, radius or system primitive the surface doesn't already own. If the existing system genuinely can't express the direction, stop and ask, naming the exact addition and the job it would do.

| Request | What it usually needs | The common misreading |
| --- | --- | --- |
| Bolder | A stronger meaningful contrast in scale, composition, type character or interaction | Turning up every saturation, shadow and size |
| Quieter | Less competing emphasis, with a clear focal point and the personality intact | Flattening the hierarchy or lowering readable contrast |
| More distinctive | A visual or behavioural idea developed from the subject | An unrelated fashionable effect |
| More delightful | Better feedback, continuity, or a rewarding discovery at a moment that earns it | Slowing frequent actions with repeated animation |
| Distil | Removing a competing job or redundant structure | Hiding essential information or navigation |
| Refine | Optical balance, rhythm, type detail and state consistency | Arbitrary pixel nudges with no visible reason |
| Harden | Real content, loading, error, input and viewport edge cases | Redesigning the visual language |
| Overdrive | One technically extraordinary moment suited to the surface | Several competing effects, or ambition hiding weak fundamentals |

## Bolder

A section usually reads flat because it opted out of moves its neighbours already make. Compare it with the rest of the page (the display type at full strength, the signature motif, the density and pacing) and bring it up to that level in the system's own vocabulary. The bolder version should look more like the same brand, not less. Commit to one decisive move, then calm what surrounds it so the move is legible; if every element got louder, the section got flatter. Give it its own rhythm so it reads as a peak.

The skeleton test: strip the copy from the planned section. If the bare structure still says what the section is and why it matters, the boldness is in the design. If it only works once the words return, the boldness is just text size.

## Quieter

Assess before cutting: find what's competing, and keep what carries the identity. Reduce by dimension (colour, visual weight, motion, composition) rather than everywhere at once, and keep one clear focal point.

## Delight

Find the moment that earns it: first run, completion, a rare success, an empty state. Define one delight thesis that fits the brand's emotional range, build it for that moment, and protect the frequent paths from it.

## Distil

Find the essence first: the one job, the content that serves it. Then cut by dimension (information architecture, visual, layout, interaction, content) until each remaining element earns its place.

## Harden

Run the extreme-input matrix: empty, one, many, very long, special characters, other languages and directions, slow and failed networks, refresh mid-flow, double submits. Build the values the way [worst-case-data.md](../../verify/references/worst-case-data.md) says: plausible or schema-backed, entered through the fixture rather than the styles. Fix text containers that assume English lengths, give every failure a real message, validate on the server too, and keep one failing component from blocking the whole interface.

## Overdrive

Context decides what extraordinary means (see `explore/references/expressive-interaction.md`). This request misfires most often, so propose two or three directions of different technique and ambition with their costs before building, then build the one chosen and iterate against the rendered result. It changes how the interface feels, not what the product does. Check it with the removal test (is it missed?), the device test (smooth on mid-range hardware?) and the context test (right for this brand?).
